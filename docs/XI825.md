# Z-Com LANEscape XI-825 wireless CF card

The native emulator's `--xi825` option attaches a PRISM/HFA384x station card
in the primary PCMCIA socket. The station connects to an open virtual access
point named **BE300**, channel **3**, BSSID **02:42:45:33:30:30**. Traffic uses
the existing GXemul Ethernet/IP gateway, DHCP and DNS backend. Nearby physical
Wi-Fi networks, ad-hoc mode, and browser/Android selection are not supported.
WEP test fixtures are available as described below.

## Driver installation

`XI825_BE300_v110.exe` is a local prerequisite; it is not redistributed. It is
a WinZip self-extracting archive containing `XI-825/xi825.cbea`. For example:

```sh
7z x /path/to/XI825_BE300_v110.exe -o/tmp/xi825-driver
build-host/be300-install --output /tmp/xi825-nand.bin \
  /path/to/All_nand_300.bin /tmp/xi825-driver/XI-825/xi825.cbea
build-host/be300 --nand /tmp/xi825-nand.bin --xi825 --rtc-host-time
```

The package supplies the MIPS R4000 `nb825be.dll` miniport and `wlu.exe`
(Wireless LAN Setting), registering adapter `xi8001`. Use a separate NAND
copy for tests: the emulator saves guest filesystem and registry changes on
orderly shutdown. The package and guest executables run unmodified.

With the current minimal CIS, WinCE asks for a driver on first insertion.
Enter **`nb825be`**, without `.dll`, using the on-screen keyboard. The driver's
own `Install_Driver` export creates the matching registry entry; it appends
the extension itself. This registers a separate adapter named
**IEEE 802.11 Wireless LAN CF Card**. In **Connections**, create a LAN profile,
select that adapter, leave IP/DNS auto-detection enabled, and finish. Restart
the guest when WinCE requests it to apply the adapter's IP settings. The
vendor utility is available as **Wireless LAN Setting** in the main menu.

`--net-mac aa:bb:cc:dd:ee:ff` also applies to XI-825. `--xi825` and
`--ne2000` are mutually exclusive and require a NAND boot. One `--cf` image
can occupy the secondary socket, whose MMIO is not yet guest-visible.
Desktop VM setup/settings offers the same card selection; existing JSON
configurations default `enable_xi825` to false.

## CIS and hardware evidence

The model implements the card's station-firmware host interface, rather than
instruction emulation of its embedded firmware. Its register, LTV record,
FID, BAP, descriptor and event definitions are corroborated by:

- Linux v6.6 [hostap_wlan.h](https://github.com/torvalds/linux/blob/v6.6/drivers/net/wireless/intersil/hostap/hostap_wlan.h)
  (16-bit PC Card register map, command/event bits, RX/TX and scan descriptors).
- Linux v6.6 [hostap_common.h](https://github.com/torvalds/linux/blob/v6.6/drivers/net/wireless/intersil/hostap/hostap_common.h)
  (PRISM station configuration/information RIDs and component identities).
- The supplied `nb825be.dll`, preferred image base `0x10000000`:

| Address | Driver behavior |
| --- | --- |
| `0x10007314`, `0x10007488` | Wait for CMD busy to clear, issue commands, poll EVSTAT bit 4, check STATUS, acknowledge completion. |
| `0x100078E8`, `0x10007AC4` | Select a FID/RID through either BAP, seek, transfer words and odd trailing bytes. |
| `0x10008238`–`0x100082BC` | Verify an odd-length TX packet's trailing sentinel by seeking to its odd end offset, then combining two reads from word boundaries; OFFSET bit 0 is ignored. |
| `0x10008AE8`, `0x10008C50` | ACCESS read and ACCESS-with-write for little-endian word-count/type/value records; verify staged writes through BAP before committing. |
| `0x10006880` | Configure station records and allocate seven TX FIDs. |
| `0x10002C98`, `0x10002CC4` | Write the 60-byte TX descriptor then the 802.3/SNAP frame at offset `0x2E`; the Ethernet length at `0x3A` is network order. |
| `0x10002D1C` | Issue TX with reclaim (`0x010B`). Ethernet mode uses TX control zero; reclaim, rather than an unconditional TX-success interrupt, returns the FID. |
| `0x10002ED0`–`0x10002F44` | CURRENTTXRATE RID returns a rate-selection bit: `8` means 11 Mbps. |
| `0x1000EA6C`–`0x1000EB08` | Read firmware CIS RID `0xFD13`, accept manufacturer `0xD601`. |
| `0x1000A8AC` | `Install_Driver` implements WinCE's user-selected driver registration path. |

The BE-300 socket, attribute-window and IRQ routing reuse the existing CF
model and its hardware citations; no GXemul submodule changes are required.

entry, and the standard PRISM COR at attribute address `0x3E0`. Its complete
byte sequence is an emulated configuration, not a captured XI-825 EEPROM.
WinCE's `pcmcia.dll` at `0x01988C30` CRCs tuple payloads for DEVICE, VERS_1
(through the first two strings), CONFIG, CFTABLE_ENTRY and MANFID. Consequently
this CIS produces `Z-Com-LANEscape/XI-825-63C0`, whereas the vendor INF
pre-registers `Z-Com-LANEscape/XI-825-51ED`. Do not force the guest checksum
or add arbitrary CIS padding to manufacture that match. Driver selection
must use WinCE's normal registration path until captured CIS bytes are available.

Firmware identity values describe the emulated PRISM station implementation;
they are not claimed as a dump of a particular physical card's firmware.
Unsupported commands/RIDs return an error. BAP accesses are bounded and do
not wrap into another FID. Configuration takes effect on ACCESS-with-write,
and device interrupt events remain pending independently of INTEN until acked.

## Tests

`ctest --test-dir build-host -R 'xi825|vm_config' --output-on-failure`
checks tuple structure, configuration/reset, command status, unknown RIDs,
both BAPs, odd-offset sentinel verification, bounded transfers, interrupt
masking/acknowledgment, virtual AP association, packet framing, reclaim,
receive queue backpressure, and desktop
configuration compatibility. These tests do not need the vendor package or NAND.

Local guest validation additionally requires the supplied driver and NAND,
both serial logs, and screenshots of the utility and a network transaction.

Validated on 2026-10-24 with the unmodified WinCE 3.0 NAND and vendor package:

- All 13 asset-free CTests passed, as did the separate cold-boot regression.
- XI-825 tests passed with AddressSanitizer and UndefinedBehaviorSanitizer.
- Wireless LAN Setting displayed the virtual AP, channel 3 and 11 Mbps.
- Normal driver registration persisted across reboot; DHCP assigned `10.0.0.1`,
  gateway/DNS `10.0.0.254`.
- The WinCE browser loaded a host-served HTTP page and resolved/loaded
  `http://example.com/`. Odd-length DNS transmission exposed and verified the
  BAP word-boundary seek behavior above.
- The source NAND remained unchanged; installation and guest settings used a copy.

## WEP fixture

`BE300_WIFI_SECURITY=wep BE300_WIFI_KEY=12345` selects a secured BE300 AP.
The station must program matching default-key bytes, select a valid transmit
slot, and enable privacy before association. Incorrect keys remain
unassociated. Firmware INIT preserves the AP configuration but clears the
station keys. See [WL54CF.md](WL54CF.md#secured-virtual-ap-fixtures) for the
shared test fixture. XI-825 deliberately does not advertise WPA/TKIP or CCMP
firmware offload; those require host cipher processing beyond this model.
