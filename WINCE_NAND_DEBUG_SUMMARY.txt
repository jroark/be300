QUICK SUMMARY: ROOT CAUSE IDENTIFIED
================================================================================

THE PROBLEM:
  NK.exe initialization gets stuck in an infinite loop polling for an 
  interrupt status that never becomes non-zero. The emulator's VRC4173 
  latch stores register values but lacks hardware behavior side effects.

THE KEY REGISTER:
  Address: 0x0A001134 (GIU Interrupt Control)
  Accesses: 229 writes (59% of all VRC4173 traffic during the 30-second boot)
  Pattern: Alternating writes of 0x1 and 0x0 (enable/disable interrupt signals)
  
  Current behavior: Values are stored in latch, then immediately returned on read
  Required behavior: Writes should trigger real side effects (update status regs)

THE BLOCKING BEHAVIOR:
  After the write sequence to 0x1134 completes, NK.exe enters an infinite loop
  that polls other registers (likely 0x1110, 0x1120, or 0x1128) expecting them
  to change based on the interrupt enable sequence. They never do, so the CPU
  spins forever.

================================================================================
THE INFINITE LOOP EXPLAINED
================================================================================

PHASE 1: Write Sequence (PC 0x80F0A654, 0x80F0A670)
  [VRC4173] W PA=0x0A001134 val=0x1  ← Enable interrupt
  [VRC4173] W PA=0x0A001134 val=0x0  ← Disable interrupt
  ... (pattern repeats ~115 times) ...
  
  What should happen:
    - Writing to 0x1134 enables/disables the GIU interrupt system
    - As a side effect, status bits in nearby registers should be set/cleared
    
  What actually happens:
    - Value stored in latch
    - No hardware behavior triggered
    - Related status registers unchanged

PHASE 2: Polling Loop (PC 0xffffffffa0079598)
  After the 0x1134 write sequence completes, NK.exe moves to:
  
  [BE300] Progress: 400M instrs, PC=0xffffffffa0079598
  [BE300] Progress: 451M instrs, PC=0xffffffffa0079598  ← Same PC for minutes
  [BE300] Progress: 502M instrs, PC=0xffffffffa0079598
  ...
  [BE300] Emulation stopped after 4680002222 instructions
  
  NK.exe is spinning in a tight loop (likely 3-4 instructions) checking for:
  - An interrupt status bit that should have been set by 0x1134 write
  - Or a pending interrupt flag in SYSINT1REG (0x0060)
  - Or a GIU status bit in 0x1110 or 0x1120
  
  Since nothing was actually enabled, the status bits stay 0x0 forever.

  Current:  Latch (stores value)
  Needed:   Side effects on write
  Action:   When written to 0x1134:
            - Extract control bits from write value
            - Update GIU status registers (0x1110, 0x1120, 0x1128)

  Registers: 0x1100-0x1130 (GIU Interrupt Unit)
  Current:   Write-only storage

  Details:
    0x1110 — GIU Interrupt Status (reads return pending bits)
    0x1120 — GIU Interrupt Status 2 (alternate status register)
    0x1128 — GIU Interrupt Control
    0x112C — GIU Interrupt Status Clear

  Registers: 0x0980, 0x0984, 0x0988, 0x0C00-0x0C30
  Current:   Configuration storage (no behavior)
  Possible:  Real hardware might have side effects or state machines
  Example:   Writing 0x0980=1 might enable FMC controller
             Then 0x0984 might return "ready" status instead of 0x0

LOW (Priority 4 - Completeness):
  Register: 0x0060 (SYSINT1REG - Aggregate Interrupt Status)
  Current:  Partially implemented with W1C (write-1-to-clear)
  Needed:   Update on GIU enables/disables
